What I built

  • Architecture built to grow. Split the system into nine decoupled packages, from preprocessing and retrieval to drafting, evaluation and the web app, with Pydantic contracts at every LLM boundary. Evaluation runs separately from inference, on versioned run artifacts.
  • A full-stack review app. Built a Next.js 16 (App Router) and React 19 frontend with Server Components in strict TypeScript, a FastAPI REST API on SQLAlchemy, Alembic and PostgreSQL, and a scheduled job that drafts replies to new emails every two hours.
  • Retrieval with the right context. Routed requests across 11 categories, combined Cohere embeddings with PostgreSQL/pgvector search, and used Haiku reranking to prioritize evidence before drafting.
  • A reusable knowledge pipeline. Turned historical agent replies into source-grounded knowledge. The integrated pipeline raised reported correct drafting from 45% to 88% and top-5 retrieval from 70% to 91%.
  • Preparation before indexing. Added GLiNER/Presidio PII masking, MPNet semantic clustering and DeBERTa NLI grounding checks to limit personal-data exposure and keep answers traceable to their sources.
  • Repeatable prompt optimization. Replaced ad hoc tuning with DSPy/GEPA against defined classification and safety metrics, making prompt selection repeatable and quality changes measurable.
  • Guardrails in code, not prompts. Checks every figure and link in a draft against its cited sources, gates on classifier confidence, isolates untrusted email text from the prompt, and keeps a person reviewing every draft. An offline evaluation harness tracks retrieval, citation and refusal quality for every run.
  • Strict quality gates. ESLint, Prettier, Vitest and React Testing Library on the frontend; Ruff with a complexity limit, mypy, docstring coverage, pytest and pre-commit hooks on the backend.
