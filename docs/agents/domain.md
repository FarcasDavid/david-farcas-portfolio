# Domain docs

## Read before exploring domain concepts or decisions

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root defines domain terminology.
- `docs/adr/` holds architectural decision records; read entries relevant to the area being explored.

If these documents are absent, proceed silently. Create them lazily through the domain-modeling workflow when terms or decisions are resolved.

## Use recorded terminology and decisions

Use glossary terms in issues, proposals, hypotheses, and tests. When a needed concept is missing, reconsider the wording or note the gap for domain modeling.

Surface conflicts with existing ADRs explicitly, identifying the decision and explaining why it should be revisited.
